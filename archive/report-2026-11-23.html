01

本周最大的事件不是谁上榜，而是「榜单失效」

02

Agent skill 从「通用能力」切成「职业资格」

本周 5 个 skill 项目合计 16,593 星，全部绑定具体职业动作：跨平台调研（last30days-skill 4,731）、视频剪辑（ffmpeg-skill 3,748）、计划评审（plannotator 2,815）、设计交付（stitch-skills 2,683）、证券交易（claude-trading-skills 2,616）。上周的主题是「给 agent 装审美」，这周换成了「给 agent 发执照」——从改善输出观感，转向接管具体岗位的流程。

这也意味着 skill 的评价标准变了：不再看「生成得像不像人做的」，而看「能不能稳定跑完一条业务流程」。

08

噪音：75 个仿冒仓库

这是本周最值得写进方法论的一件事：高星新项目榜单可以被批量伪造。

结论先说。在「7 天内创建、star > 300」的 506 个仓库里，有 75 个属于同一个模板化簇（14.8%）。它们不是开源项目，是黑帽 SEO 的引流页。不要下载、不要执行其中任何文件。本报告不会给出这些仓库的可点击链接。
证据一 · 时间01 / TIMING

75 个仓库的创建时间集中在 2026-11-21 同一天。正常的新项目分布不会出现这种单日聚集。

证据二 · 星数02 / STARS

全部落在 353–366 这个极窄区间内，且 fork 数全部为 0。真实项目的 star 分布是长尾的，且几乎不可能 75 个项目同时零 fork。

证据三 · 内容03 / CONTENT

抽查两个仓库（birddebug/cinema-4d-win、Mnowak64/iobit-uninstaller-pro-win），文件列表完全一致：README.md、LICENSE、CHANGELOG.md、docs/，没有任何可执行代码或安装包。

README 是同一套模板：「A Windows reference and setup guide for …」+ 一排徽章，指向商业软件的下载引导。

证据四 · 命名04 / NAMING

统一以 -win 结尾，覆盖 Cinema 4D、InDesign、AutoCAD、Photoshop、IObit、Total Commander、JetBrains、Figma、Tableau 等商业软件名。命名策略是抢占搜索关键词，不是开发软件。

为什么这件事重要。它把 star 作为信号的最后一点可信度打穿了：上一期我们还在讨论 star/watcher 比 300 是否异常，这一期直接出现了成本更低的伪造方式——75 个仓库、零代码、统一刷到 350 星，就足以进入「高星新项目」的筛选结果。
可操作的防御：只看 star 不够，至少同时看 fork 数、文件构成、创建时间的聚集度。三者同时异常，基本可以判定为噪音。

GTA 重编译簇会不会继续扩散

本周已有 4 个同主题项目。如果下周出现第 5、第 6 个（尤其是有实质进展的），说明这是新一轮平台重编译潮的开始；如果全部停在「研究 / 进展记录」阶段，那它只是一次话题爆发。可验证指标：同主题新仓库数量、以及是否出现可运行的构建。

官方 MCP 会不会挤掉第三方封装

本周 5 个官方项目占周榜 37.7%。观察下周是否还有 Chrome、Meta、阿里以外的厂商跟进，以及第三方封装类项目（如上一期的 addyosmani/agent-skills）能否回到榜内。如果连续两周官方占比超过 35%，中间商模式基本可以判定为退潮。

03

仿冒簇会被清理吗

75 个仓库目前仍可访问。若 GitHub 在下周批量封禁，说明平台侧有检测能力；若继续存在并扩到其他关键词（如 -mac），则「高星新项目」这个数据源需要长期做清洗。可验证指标：这 75 个仓库的存活数量。

t3code 能否守住月榜第一

它连续两期月增第一（33,583 → 41,514），但两周都没有出现在周榜。如果下周月增继续上升却仍不进周榜，说明 GitHub 的周榜算法对「已成名项目」有抑制，这会影响所有基于周榜的趋势判断。
